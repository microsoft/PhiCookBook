# **ការកំណត់តម្លៃស៊េរី Phi**

Model quantization សូម្បីយោងដល់ដំណើរការនៃការបង្ហាញផែនទីប៉ារ៉ាម៉ែត្រ (ដូចជា សំលេងទម្ងន់ និង តម្លៃសកម្មភាព) ក្នុងម៉ូឌែលបណ្តាញជីវចលពីជួរតម្លៃធំមួយ (ទូទៅជាជួរតម្លៃបន្ត) ទៅជាជួរតម្លៃមានកំណត់តូច។ បច្ចេកវិទ្យានេះអាចកាត់បន្ថយទំហំ និង ភាពស្មុគស្មាញកុំព្យូតิงនៃម៉ូឌែល និងធ្វើឲ្យប្រសិទ្ធភាពប្រតិបត្តិការរបស់ម៉ូឌែលល្អប្រសើរឡើងនៅក្នុងបរិបទដែលមានធនធានកំណត់ ដូចជា ឧបករណ៍ចល័ត ឬ ប្រព័ន្ធបញ្ចូល។ Model quantization ទទួលបានការបង្រួមទំហំដោយកាត់បន្ថយភាពច្បាស់នៃប៉ារ៉ាម៉ែត្រ ប៉ុន្តែវាក៏បង្កើតការបាត់បង់ភាពច្បាស់មួយចំនួនផងដែរ។ ដូច្នេះ នៅក្នុងដំណើរការកំណត់តម្លៃ គួរតែសមតុល្យទំហំម៉ូឌែល ភាពស្មុគស្មាញកុំព្យូតิง និងភាពច្បាស់។ វិធីសាស្ត្រកំណត់តម្លៃពេញនិយមរួមមាន fixed-point quantization, floating-point quantization ល។ អ្នកអាចជ្រើសយុទ្ធសាស្ត្រកំណត់តម្លៃដែលសមស្របតាមសេចក្តីណែនាំ និងតម្រូវការ។

យើងសង្ឃឹមនឹងបានដាក់ GenAI model ទៅឧបករណ៍ឆ្វេង និងអនុញ្ញាតឲ្យឧបករណ៍ច្រើនជាងនេះចូលរួមនៅក្នុងសេណារីយ៉ូ GenAI ដូចជា ឧបករណ៍ចល័ត, AI PC/Copilot+PC, និងឧបករណ៍ IoT ប្រពៃណី។ តាមរយៈម៉ូឌែលដែលបានកំណត់តម្លៃ យើងអាចដាក់វាទៅឧបករណ៍ឆ្វេងផ្សេងៗគ្នាតាមប្រភេទឧបករណ៍។ ប្រកបដោយស៊ុមជាមួយស៊ុមល្បឿនម៉ូឌែល និង ម៉ូឌែល quantization ដែលផ្តល់ដោយអ្នកផលិតរឹងថ្នាំ យើងអាចសាងសង់សេណារីយ៉ូប្រើប្រាស់ SLM ល្អប្រសើរជាងមុន។

នៅក្នុងសេណារីយ៉ូកំណត់តម្លៃ យើងមានភាពច្បាស់ខុសគ្នា (INT4, INT8, FP16, FP32)។ ខាងក្រោមជាការពិពណ៌នាអំពីភាពច្បាស់បង្កើតប្រូចង់ប្រើសៀងសារ

### **INT4**

INT4 quantization ជាវិធីកំណត់តម្លៃដ៏ខ្លាំងដែលបម្លែងទម្ងន់ និង តម្លៃសកម្មភាពនៃម៉ូឌែលទៅជាលេខគត់ 4 ប៊ីត។ INT4 quantization ទូទៅនាំឲ្យមានការបាត់បង់ភាពច្បាស់ច្រើនទៀតដោយសារជួរតម្លៃដែលតូចជាង និងភាពច្បាស់ទាបជាង។ ទោះយ៉ាងណា ជាប្រៀបធៀបនឹង INT8 quantization, INT4 អាចកាត់បន្ថយតម្រូវការផ្ទុក និងភាពស្មុគស្មាញគណនាដល់តិចជាង។ គួរយោងថា INT4 quantization ពេលភាគច្រើនមានករណីពិបាកក្នុងការអនុវត្តនៅក្នុងការអនុវត្តន៍ពិតប្រាកដ ព្រោះភាពច្បាស់ដែលទាបពេកអាចបណ្តាលឲ្យមានការបាត់បង់ប្រសិទ្ធភាពម៉ូឌែលយ៉ាងច្រើន។ លើសពីនេះទៀត មិនមែនឧបករណ៍ទាំងអស់ទ្រទ្រង់ប្រតិបត្តិការផ្នែក INT4 ទេ ដូច្នេះ ត្រូវគិតពីភាពឆបគ្នានៃឧបករណ៍ពេលជ្រើសវិធីសាស្ត្រកំណត់តម្លៃ។

### **INT8**

INT8 quantization ជាដំណើរការបម្លែងទម្ងន់ និង តម្លៃសកម្មភាពរបស់ម៉ូឌែលពីលេខចល័តទៅជាលេខគត់ 8-ប៊ីត។ ទោះបីជាជួរលេខដែលត្រូវបានតំណាងដោយលេខគត់ INT8 តូច និងមានភាពច្បាស់តិចក៏ដោយ វាអាចកាត់បន្ថយតម្រូវការផ្ទុក និងការគណនាសេដ្ឋកិច្ចយ៉ាងច្រើន។ ក្នុង INT8 quantization ទម្ងន់ និង តម្លៃសកម្មភាពនៃម៉ូឌែលត្រូវបានដំណើរការក្នុងដំណាក់កាលកំណត់តម្លៃ រួមមានការលាយកម្រិត និង អូហ្វសេត ដើម្បីរក្សាព័ត៌មានលេខចល័តដើមឲ្យបានច្រើនបំផុត។ នៅពេលអនុវត្ត inference តម្លៃដែលបានកំណត់នឹងត្រូវបាន dequantize កម្មវិធីទៅលេខចល័តសម្រាប់ការគណនា ហើយបន្ទាប់មកកំណត់ឡើងវិញទៅ INT8 សម្រាប់ជំហានបន្ទាប់។ វិធីនេះអាចផ្តល់ភាពច្បាស់គ្រប់គ្រាន់ក្នុងកម្មវិធីភាគច្រើន ខណៈដែលរក្សាបានភាពប្រសើរនៃការគណនាបានខ្ពស់។

### **FP16**

ទ្រង់ទ្រាយ FP16 ឬថា 16-bit floating point numbers (float16) កាត់បន្ថយកំណត់ទំហំអង្គចងចាំជាកន្លះបរិមាណពាក់ព័ន្ធជាមួយលេខចល័ត 32-ប៊ីត (float32) ដែលមានអត្ថប្រយោជន៍ច្រើនក្នុងកម្មវិធី deep learning ទំហំធំ។ ទ្រង់ទ្រាយ FP16 អនុញ្ញាតឲ្យផ្ទុកម៉ូឌែលធំជាង ឬ ដំណើរការទិន្នន័យច្រើនជាងនៅក្នុងកម្រិតអង្គចងចាំ GPU ដូចគ្នា។ នៅពេលឧបករណ៍ GPU សម័យទំនើបបន្តគាំទ្រ FP16 operations ការប្រើទ្រង់ទ្រាយ FP16 ក៏អាចនាំឲ្យមានការកាត់បន្ថយពេលគណនាបានផងដែរ។ ទោះបីជាយ៉ាងណា ទ្រង់ទ្រាយ FP16 ក៏មានគុណវិបត្តិជាស្និទ្ធផ្ទាល់របស់ខ្លួន គឺភាពច្បាស់ទាប ដែលអាចនាំឲ្យមានភាពអស្ថិតិស្ថិតិគណិត ឬ បាត់បង់ភាពច្បាស់នៅក្នុងករណីខ្លះ។

### **FP32**

ទ្រង់ទ្រាយ FP32 ផ្តល់ភាពច្បាស់ខ្ពស់ជាង និងអាចតំណាងអស់បានជួរតម្លៃធំៗបានយ៉ាងត្រឹមត្រូវ។ ក្នុងសេណារីយ៉ូដែលមានប្រតិបត្តិការគណិតស្មុគស្មាញ ឬ ត្រូវការវិវត្តន៍លទ្ធផលដែលមានភាពច្បាស់ខ្ពស់ ទ្រង់ទ្រាយ FP32 គឺជាជម្រើសức។ ទោះយ៉ាងណា ភាពច្បាស់ខ្ពស់ក៏មានន័យថាត្រូវការអង្គចងចាំច្រើន និងពេលគណនាអនុវត្តប្រវែង។ សម្រាប់ម៉ូឌែល deep learning ទំហំធំ ជាពិសេសពេលដែលមានប៉ារ៉ាម៉ែត្រម៉ូឌែលច្រើន និងទិន្នន័យបរិមាណធំនោះទ្រង់ទ្រាយ FP32 អាចបណ្តាលឲ្យមានអង្គចងចាំ GPU មិនគ្រប់គ្រាន់ ឬ ការរអិចនៃល្បឿន inference ។

នៅលើឧបករណ៍ចល័ត ឬ ឧបករណ៍ IoT យើងអាចបម្លែងម៉ូឌែល Phi-3.x ទៅ INT4 ខណៈដែល AI PC / Copilot PC អាចប្រើភាពច្បាស់ខ្ពស់ជាងដូចជា INT8, FP16, FP32។

នៅពេលនេះ អ្នកផលិតរឹងថ្នាំផ្សេងៗមានស៊ុមខុសៗគ្នាដើម្បីគាំទ្រម៉ូឌែលបង្កើត (generative models) ដូចជា Intel's OpenVINO, Qualcomm's QNN, Apple's MLX, និង Nvidia's CUDA ល។ សម្របជាមួយការកំណត់តម្លៃម៉ូឌែល ដើម្បីបញ្ចប់ការដាក់នៅក្នុងសួនធម្មតា។

នៅចំណុចបច្ចេកទេស យើងមានការគាំទ្រទ្រង់ទ្រាយខុសៗគ្នាបានបន្ទាប់ពីកំណត់តម្លៃ ដូចជា PyTorch / TensorFlow format, GGUF, និង ONNX។ ខ្ញុំបានធ្វើការប្រៀបធៀបទ្រង់ទ្រាយ និងសេណារីយ៉ូប្រើប្រាស់រវាង GGUF និង ONNX។ នៅទីនេះខ្ញុំពេញចិត្តណែនាំទ្រង់ទ្រាយ ONNX quantization ដែលមានការគាំទ្រល្អចាប់ពីស៊ុមម៉ូឌែលដល់ឧបករណ៍។ នៅក្នុងជំពូកនេះ យើងនឹងផ្តោតលើ ONNX Runtime សម្រាប់ GenAI, OpenVINO, និង Apple MLX ដើម្បីអនុវត្តការកំណត់តម្លៃម៉ូឌែល (បើអ្នកមានវិធីល្អជាង អ្នកអាចផ្តល់ឲ្យយើងដោយបញ្ជូន PR)
