# ការរួមចំណែក

គម្រោងនេះស្វាគមន៍ការរួមចំណែក និងការផ្តល់យោបល់។ ការរួមចំណែកភាគច្រើនតម្រូវឱ្យអ្នកយល់ព្រមចំពោះ
កិច្ចសន្យាសិទ្ធិអ្នករួមចំណែក (CLA) ដែលប្រកាសថាអ្នកមានសិទ្ធិ ហើយពិតជាប្រើប្រាស់សិទ្ធិនោះ
ដើម្បីឱ្យយើងអាចប្រើប្រាស់ការរួមចំណែករបស់អ្នក។ សម្រាប់ព័ត៌មានលម្អិត សូមចូលមើល [https://cla.opensource.microsoft.com](https://cla.opensource.microsoft.com)

ពេលដែលអ្នកដាក់សំណើ pull request មួយ អ្នកចាត់ចែង CLA រ៉ូបតិចនឹងកំណត់ដោយស្វ័យប្រវត្តិថាតើអ្នកត្រូវផ្តល់ CLA រឺទេ ហើយដាក់ទំនាក់ទំនង PR ដោយសមរម្យ (ឧ. ការត្រួតពិនិត្យស្ថានភាព ការកំណត់សម្គាល់)។ អ្នកគ្រាន់តែបន្តតាមការណែនាំដែលរ៉ូបតិចផ្តល់។ អ្នកត្រូវធ្វើតែមួយដងតែម្ដងសម្រាប់គម្រោងទាំងអស់ដែលប្រើ CLA របស់យើង។

## ច្បាប់ការបង្ហើប

គម្រោងនេះទទួលយក [Microsoft Open Source Code of Conduct](https://opensource.microsoft.com/codeofconduct/)។
សម្រាប់ព័ត៌មានបន្ថែម សូមអាន [Code of Conduct FAQ](https://opensource.microsoft.com/codeofconduct/faq/) ឬទំនាក់ទំនង [opencode@microsoft.com](mailto:opencode@microsoft.com) ប្រសិនបើមានសំណួរឬមតិយោបល់បន្ថែម។

## ការប្រុងប្រយ័ត្នក្នុងការបង្កើតបញ្ហា

សូមកុំបើកបញ្ហា GitHub សម្រាប់សំណួរជំនួយទូទៅ ពីព្រោះបញ្ជី GitHub គួរត្រូវបានប្រើសម្រាប់ការស្នើសុំមុខងារ និងការរាយការណ៍កំហុស។ វាជួយអោយយើងតាមដានបញ្ហារឺកំហុសពិតប្រាកដពីកូដបានងាយស្រួល និងរក្សាការពិភាក្សាទូទៅឲ្យបំបែកពីកូដពិតប្រាកដ។

## របៀបរួមចំណែក

### គោលការណ៍សម្រាប់ Pull Requests

ពេលដែលដាក់សំណើ pull request (PR) ទៅកាន់គណនី Phi-3 CookBook សូមប្រើគោលការណ៍ដូចខាងក្រោម៖

- **រក្សាទុក Repository តាមរយៈ Fork**: ជានិច្ចសូម fork repository ទៅគណនីរបស់អ្នកមុនពេលធ្វើការកែប្រែ។

- **បំបែក pull requests (PR)**:
  - ដាក់ស្នើប្រភេទការផ្លាស់ប្ដូរនីមួយៗនៅក្នុង pull request ផ្សេងៗគ្នា។ ឧ. ការជួសជុលកំហុស និងការប្រសើរឡើងឯកសារប្រវត្តិរូបគួរត្រូវបានដាក់ស្នើនៅក្នុង PR ផ្សេងៗ។
  - ការកែលម្អតូចៗ និងការកែលម្អឯកសារប្រវត្តិរូបតិចតួចអាចបញ្ចូលក្នុង PR មួយជាសកលបានប្រសិនបើសមរម្យ។

- **ដោះស្រាយករណីសម្រុះជំនួសបញ្ហា (merge conflicts)**: ប្រសិនបើ pull request របស់អ្នកបង្ហាញករណីសម្រុះ ជាទូទៅអ្នកត្រូវធ្វើបច្ចុប្បន្នភាពសាខា `main` របស់អ្នកឲ្យឆ្លុះបង្ហាញ repository មេ មុនធ្វើការកែប្រែ។

- **ដាក់ស្នើការបកប្រែ**: ពេលដាក់ស្នើ PR ដើម្បីបកប្រែ សូមធានាថថតបកប្រែមានការបកប្រែសម្រាប់ឯកសារទាំងអស់​នៅក្នុងថតដើម។

### គោលការណ៍សរសេរ

ដើម្បីធានាសមរម្យគ្នាទាំងអស់ឯកសារ សូមប្រើគោលការណ៍ដូចខាងក្រោម៖

- **រៀបចំបែប URL**: វាសមរម្យឲ្យចង URL ទាំងអស់ក្នុងដោយសញ្ញាប្រអប់ចូរតាមដោយក្បាលសញ្ញាស្តើងៗ ដោយគ្មានចន្លោះបន្ថែមនៅជុំវិញឬខាងក្នុង។ ឧ. `[example](https://www.microsoft.com)`។

- **តំណដែលស្តង់ដារ**: ប្រើ `./` សម្រាប់តំណជំពូកទៅឯកសារឬថតក្នុងថតបច្ចុប្បន្ន និង `../` សម្រាប់នៅថតគូទ។ ឧ. `[example](../../path/to/file)` ឬ `[example](../../../path/to/file)`។

- **មិនអនុញ្ញាតឲ្យមានភាសាប្រទេសជាក់លាក់**: សូមប្រាកដថាតំណរបស់អ្នកមិនមានភាសាប្រទេសជាក់លាក់ណាមួយ។ ឧ. ចៀសវាង `/en-us/` រឺ `/en/`។

- **ទូទុករូបភាព**: ទូទុករូបភាពទាំងអស់នៅក្នុងថត `./imgs`។

- **ឈ្មោះរូបភាពពិពណ៌នា**: ឈ្មោះរូបភាពត្រូវមានអត្ថន័យប្រើអក្សរអង់គ្លេស លេខ និងសញ្ញាពិសេសដូចជារបារឈរ។ ឧ. `example-image.jpg`។

## ដំណើរការការងារ GitHub

ពេលដែលអ្នកដាក់ស្នើ pull request ដំណើរការដូចខាងក្រោមនឹងត្រូវបញ្ចេញដើម្បីផ្ទៀងផ្ទាត់ប្រែប្រួល។ សូមអនុវត្តក្នុងការណែនាំខាងក្រោមសម្រាប់បញ្ចាន pull request ឲ្យជួបលក្ខខណ្ឌការត្រួតពិនិត្យ:

- [ត្រួតពិនិត្យផ្លូវទំនេរបំបែកខូច](#ត្រួតពិនិត្យផ្លូវទំនេរបំបែកខូច)
- [ត្រួតពិនិត្យ URL មិនមានភាសាប្រទេស](#ត្រួតពិនិត្យ-url-មិនមានភាសាប្រទេស)

### ត្រួតពិនិត្យផ្លូវទំនេរបំបែកខូច

ដំណើរការនេះធានាថាតំណផ្លូវទំនេរទាំងអស់ក្នុងឯកសាររបស់អ្នកត្រឹមត្រូវ។

1. ដើម្បីធានាថាតំណរបស់អ្នកដំណើរការបានត្រឹមត្រូវ សូមអនុវត្តកម្មវិធីខាងក្រោមដោយប្រើ VS Code:
    - អូសមៅលើតំណណាមួយនៅក្នុងឯកសារ។
    - ចុច **Ctrl + Click** ដើម្បីចូលទៅតំណ។
    - ប្រសិនបើអ្នកចុចលើតំណណាមួយហើយវាមិនដំណើរការក្នុងម៉ាស៊ីនរបស់អ្នក វានឹងបញ្ចេញដំណើរការនេះហើយមិនដំណើរការនៅ GitHub ទេ។

1. ដើម្បីជួសជុលបញ្ហានេះ សូមអនុវត្តកម្មវិធីខាងក្រោមដោយប្រើជម្រើសផ្លូវដែល VS Code ផ្តល់:
    - វាយ `./` ឬ `../`។
    - VS Code នឹងផ្តល់ជម្រើសសម្រាប់អ្នកជ្រើសតាមអ្វីដែលអ្នកវាយ។
    - បន្តតាមផ្លូវដោយចុចលើឯកសារឬថតដែលចង់បាន ដើម្បីធានាផ្លូវត្រឹមត្រូវ។

បន្ទាប់ពីអ្នកបញ្ចូលផ្លូវទំនេរត្រឹមត្រូវ សូមរក្សាទុក និងបញ្ជូនការផ្លាស់ប្ដូររបស់អ្នក។

### ត្រួតពិនិត្យ URL មិនមានភាសាប្រទេស

ដំណើរការនេះធានាថា URL ណាមួយលើគេហទំព័រមិនមានភាសាប្រទេសជាក់លាក់ណាមួយ។ ពីព្រោះ repository នេះអាចចូលដំណើរការបានសកល វាសំខាន់ក្នុងការធានាថា URL មិនមានភាសាប្រទេសរបស់អ្នក។

1. ដើម្បីផ្ទៀងផ្ទាត់ថា URL នៃអ្នកមិនមានភាសាប្រទេស សូមអនុវត្តកម្មវិធីខាងក្រោម៖

    - ត្រួតពិនិត្យអត្ថបទដូចជា `/en-us/`, `/en/`, ឬភាសារួមផ្សំផ្សេងទៀតនៅក្នុង URL។
    - ប្រសិនបើមិនមាននៅក្នុង URL របស់អ្នក អ្នកនឹងផ្លាស់បង់ត្រួតពិនិត្យជោគជ័យ។

1. ដើម្បីជួសជុលបញ្ហានេះ សូមអនុវត្តកម្មវិធីខាងក្រោម៖
    - បើកផ្លូវឯកសារដែលត្រូវបានបញ្ជាក់ដោយដំណើរការនេះ។
    - លុបភាសាប្រទេសចេញពី URL។

បន្ទាប់ពីលុបភាសាប្រទេសរួច សូមរក្សាទុក និងបញ្ជូនការផ្លាស់ប្តូររបស់អ្នក។

### ត្រួតពិនិត្យ URL ខូច

ដំណើរការនេះធានាថា URL ណាមួយក្នុងឯកសាររបស់អ្នកដំណើរការល្អ និងបង្វិលកូដស្ថានភាព 200។

1. ដើម្បីផ្ទៀងផ្ទាត់ថា URL របស់អ្នកដំណើរការត្រឹមត្រូវ សូមអនុវត្តកម្មវិធីខាងក្រោម៖
    - ពិនិត្យស្ថានភាព URL នៅក្នុងឯកសារ។

2. ដើម្បីជួសជុល URL ខូច សូមអនុវត្តកម្មវិធីខាងក្រោម៖
    - បើកឯកសារដែលមាន URL ខូច។
    - ពិនិត្យហើយធ្វើបច្ចុប្បន្នភាព URL ទៅត្រឹមត្រូវ។

បន្ទាប់ពីអ្នកជួសជុល URL បាន សូមរក្សាទុក និងបញ្ជូនការផ្លាស់ប្តូររបស់អ្នក។
