Phi — це серія моделей штучного інтелекту з відкритим вихідним кодом, розроблена Microsoft.

Наразі Phi є найпотужнішою та найбільш економічною невеликою моделлю мови (SLM), з дуже хорошими показниками у багатомовності, мисленні, генерації тексту/чатів, кодуванні, зображеннях, аудіо та інших сценаріях.

Ви можете розгортати Phi у хмарі або на пристроях на межі мережі, а також легко створювати генеративні AI-додатки з обмеженою обчислювальною потужністю.

Дотримуйтесь цих кроків, щоб почати використовувати ці ресурси:

> git clone --filter=blob:none --sparse https://github.com/microsoft/PhiCookBook.git

> ```

## Відповідальний Штучний Інтелект 

Microsoft прагне допомагати нашим клієнтам відповідально використовувати наші AI-продукти, ділитися досвідом і будувати довірчі партнерства за допомогою таких інструментів, як Нотатки прозорості та Оцінки впливу. Багато з цих ресурсів можна знайти за адресою [https://aka.ms/RAI](https://aka.ms/RAI).
Підхід Microsoft до відповідального AI ґрунтується на наших принципах ШІ: справедливості, надійності та безпеки, конфіденційності та захисту, інклюзивності, прозорості та підзвітності.

Великі моделі природної мови, зображень та мови — такі, що використовуються в цьому прикладі — потенційно можуть поводитися несправедливо, ненадійно чи образливо, що може спричинити шкоду. Будь ласка, ознайомтесь з [Нотаткою прозорості служби Azure OpenAI](https://learn.microsoft.com/legal/cognitive-services/openai/transparency-note?tabs=text), щоб дізнатися про ризики та обмеження.

Рекомендований підхід до мінімізації цих ризиків – включити в архітектуру систему безпеки, яка може виявляти та запобігати шкідливій поведінці. [Azure AI Content Safety](https://learn.microsoft.com/azure/ai-services/content-safety/overview) забезпечує незалежний рівень захисту, здатний виявляти шкідливий контент, створений користувачами та ШІ, у програмах і сервісах. Azure AI Content Safety включає API для тексту та зображень, які дозволяють виявляти шкідливий матеріал. У Microsoft Foundry служба Content Safety дозволяє переглядати, досліджувати та випробовувати приклади коду для виявлення шкідливого контенту в різних модальностях. Наступна [документація для швидкого старту](https://learn.microsoft.com/azure/ai-services/content-safety/quickstart-text?tabs=visual-studio%2Clinux&pivots=programming-language-rest) допоможе вам зробити запити до служби.

Іншим аспектом, який потрібно враховувати, є загальна продуктивність застосунку. В обробці мультимодальних та мультимодельних застосунків під продуктивністю ми розуміємо, що система працює так, як ви та ваші користувачі очікуєте, зокрема не генерує шкідливі результати. Важливо оцінювати продуктивність вашого загального застосунку з використанням [оціночних засобів продуктивності, якості, ризиків та безпеки](https://learn.microsoft.com/azure/ai-studio/concepts/evaluation-metrics-built-in). Ви також можете створювати та оцінювати з [кастомними оціночними засобами](https://learn.microsoft.com/azure/ai-studio/how-to/develop/evaluate-sdk#custom-evaluators).

Ви можете оцінювати ваш AI-застосунок у середовищі розробки з використанням [Azure AI Evaluation SDK](https://microsoft.github.io/promptflow/index.html). Якщо у вас є тестовий набір даних або ціль, генерації вашого генеративного AI-застосунку кількісно вимірюються вбудованими або кастомними оцінювачами на ваш вибір. Щоб почати працювати з azure ai evaluation sdk для оцінки вашої системи, ви можете слідувати [інструкції швидкого старту](https://learn.microsoft.com/azure/ai-studio/how-to/develop/flow-evaluate-sdk). Після виконання запуску оцінки ви можете [візуалізувати результати у Microsoft Foundry](https://learn.microsoft.com/azure/ai-studio/how-to/evaluate-flow-results).
